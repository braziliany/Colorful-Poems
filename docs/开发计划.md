# 彩云诗词桌面天气｜开发计划

> 项目：iOS Scriptable 中号小组件  
> 主文件：`src/widget.js`  
> 建立日期：2026-07-30  
> 当前阶段：第一阶段代码审计完成，等待确认后实施修改

## 一、开发目标

- 保留现有水平双栏布局、配色、字号、间距和圆角背景。
- 保留彩云天气、天气预警、农历、诗词、日历、提醒、电池和背景设置等现有功能。
- 修复可能导致 `undefined`、`null`、日期对象和 `Image` 类型错误的问题。
- 所有网络请求失败时显示兜底内容，不让小组件崩溃。
- 所有传给 `addImage()` 的对象必须是有效的 Scriptable `Image`。
- 最终 `src/widget.js` 保持为可直接复制到 Scriptable 运行的单文件脚本。

## 二、第一阶段：代码审计

状态：已完成。

审计范围：

1. 完整阅读 `AGENTS.md` 和 `src/widget.js`。

## 三、第二阶段：最小范围加固

需用户确认后开始。

### 3.1 图片与 SF Symbol

- 为 `SFSymbol.named()` 增加异常捕获。
- 建立集中式安全图片兜底，避免 `addImage()` 收到 `null`、`undefined` 或非图片对象。
- 检查相册选择、透明背景裁剪和本地背景图片读取结果。
- 背景图片不存在、损坏或无法解码时继续使用当前纯色背景。

### 3.2 彩云天气

- 验证 `result`、`realtime`、`daily` 等字段确实为对象。
- 验证 `temperature`、`astro` 等字段确实为数组。
- 标准化温度、湿度和 AQI，兼容有效的数字字符串。
- 验证天气预警、生活指数、天气描述、日出日落字段的类型。
- 保留现有天气图标、文字和失败提示。

### 3.3 农历和诗词

- 验证接口业务状态和响应结构。
- 修正农历请求头与请求体类型不一致的问题。
- 避免仅根据字符串长度固定截取农历内容。
- 保证诗句、朝代和作者只有在有效字符串时才显示。
- 接口异常时继续显示现有兜底文案。

### 3.4 日历和提醒

- 验证 `CalendarEvent.today()` 和 `Reminder.all()` 的返回值是否为数组。
- 验证日程 `startDate`、`endDate` 是否为有效日期。
- 单条日程异常时只跳过该条，不清空当天所有日程。
- 暂不改变提醒事项当前的显示行为。

### 3.5 文字截断

在不重做 UI 的前提下：

- 给可压缩文字设置适度的最小缩放比例。
- 优化“星期 + 农历 + 电池”同一水平栈中的空间竞争。
- 对超长天气预警采用受控的显示策略。
- 同时检查问候语、诗句和日程标题在较窄机型上的表现。
- 防止为了增加文本行数而导致组件底部内容溢出。

## 四、第三阶段：验证

修改后必须完成：

1. 查看并复核完整 diff。
2. 检查所有远程字段的空值访问。
3. 检查每一个 `addImage()` 输入。
4. 检查是否混入浏览器或 Node.js API。
5. 做 JavaScript 语法检查。
6. 在 iPhone Scriptable 中真机运行。
7. 对比修改前后截图，确认双栏布局和视觉风格未改变。
8. 行为发生变化时同步更新 `README.md`。

## 五、验收标准

- 网络、定位、日历、提醒和相册权限失败时脚本不崩溃。
- 无效 SF Symbol 不会导致运行中断。
- 本地背景图片异常时显示纯色背景。
- 农历、天气和诗词字段缺失时显示合理兜底文本。
- 重要文字的无谓截断减少。
- 当前 UI、功能和中号组件定位保持不变。

## 六、开发安装器

状态：已实现，等待真机运行确认。

- 仓库源码和安装清单只发布彩云 Token 占位符。
- 首次安装通过 Scriptable 隐藏输入框获取 Token，并仅写入本机组件副本。
- 更新时优先复用已安装脚本中的 Token，避免重复输入。
- 安装前校验版本、下载状态和资源标记。
- 多文件写入失败时回滚到安装前版本。
- 自动更新主组件与安装器本身。
- 安装器只用于开发和真机测试阶段，正式发行后不作为运行依赖。

真机待验证：

1. 首次安装和取消输入。
2. 使用有效 Token 正常运行天气组件。
3. 从同版本重新安装和后续版本更新时保留 Token。
4. 断网、清单失败和资源下载失败时不覆盖原脚本。
