### 主要审计发现

#### 图片和背景

- `addStyleImg()` 使用 `img instanceof Image`，对 Scriptable 原生桥接对象的判断可能不够稳健。
- `SFSymbol.named()` 只有空返回兜底，没有处理直接抛出异常的情况。
- `files.readImage()` 只检查文件是否存在，没有验证文件能否成功解码为图片。
- 相册取消、无效截图和裁剪选择异常可能中断背景配置流程。

#### 日历和提醒

- `schedule.endDate.getTime()` 假定 `endDate` 一定存在且为有效日期。
- 日程时间格式化直接调用 `startDate/endDate` 的日期方法。
- 一条异常日程可能触发外层捕获，使当天全部日程变为空。
- `CalendarEvent.today()` 和 `Reminder.all()` 的结果缺少数组验证。
- 提醒数据当前会被读取，但没有参与现有界面渲染。

#### 彩云天气

- 已有总体 `try/catch` 和 fallback，基础容错较好。
- `result`、`realtime`、`daily` 只做了空值兜底，没有严格验证对象类型。
- `temperature`、`astro` 没有验证数组类型。
- 湿度和 AQI 只接受原生数字，合法数字字符串会显示为 `--`。
- 预警标题、生活指数、天气描述和日出日落仍需字符串类型检查。

#### 农历

- `lunarInfo?.data?.lunar` 已避免直接空值崩溃。
- 没有验证接口业务状态。
- 使用固定 `substring(12)` 处理旧格式，接口文本变化时可能误截有效内容。
- multipart 请求体和 `application/json` 请求头不一致。

#### 今日诗词

- 诗句正文已有字符串检查和兜底。
- 朝代、作者仅使用真值判断，没有严格验证字符串类型。
- 没有验证接口业务状态。
- 超长诗句会受单行布局限制而截断。

#### 平台兼容性

没有发现正在执行的浏览器或 Node.js API：

- 无 `document`、`window`、HTML、CSS 或 Font Awesome。
- 无 `require`、`module.exports`、`process`、`Buffer`。
- 当前主要 API 均属于 Scriptable。

### 真机截断原因

1. “星期 + 农历 + 电池”位于同一个水平栈，三段文字均限制为单行。
2. 电池文本相对不可压缩，导致中间农历优先出现省略号。
3. 天气预警标题被强制设为单行，长预警必然截断。
4. 右栏固定为 `110pt`，两栏之间还有弹性 spacer，左栏承担剩余空间。
5. 文本没有设置适度的 `minimumScaleFactor`。
6. 问候语、日程标题和诗句在长内容或窄机型上也存在同类风险。
